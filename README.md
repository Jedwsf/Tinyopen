# Tinyopen

> 一个轻量的 Windows 桌面小工具：把常用的**文件、程序、网页**分组收纳，一键批量打开。

**版本 1.3.0　·　适用平台：64 位 Windows 10 / 11　·　绿色免安装**

---

## 简介

Tinyopen 用来解决一个很日常的烦恼：每天开工要打开一堆固定软件、文档和网页，一个个点太麻烦。

用它把「上班要开的东西」放进一个分组，以后点一下就能全部打开；把「追的番」放一组，把「工作网页」放一组，互不干扰。

- 🟢 **绿色便携**：免安装，整个文件夹拷到 U 盘也能用
- 🧩 **分组管理**：文件 / 程序 / 网页都能放进分组，一键启动
- 🖱️ **拖动排序**：按住分组标题栏即可拖动换位置
- ⚡ **开机自启**：可让指定分组在 Tinyopen 启动时自动打开
- 📝 **后台记录**：每次打开成功还是失败，都有据可查

## 快速开始

1. 把整个文件夹拷到电脑任意位置，例如 `D:\Tinyopen`
2. 双击 **`Tinyopen.exe`** 运行
3. 点右上角 **加号** 新建分组 → 点分组里的 **加号** 添加文件或网页 → 完成

> ⚠️ **请连同整个文件夹一起拷贝**，不要只拷 `Tinyopen.exe`。  
> 程序需要旁边的 `.dll` 文件和 `platforms` 等子文件夹才能启动。

## 常见问题

**Q：双击没反应？**  
A：确认是把**整个文件夹**拷过来的，里面的 `.dll` 文件都在。若被杀毒软件拦截，加入信任即可。

**Q：打开某个文件失败？**  
A：点顶部 **时钟** 图标查看后台记录，会写明失败原因（如「文件不存在或路径无效」）。

**Q：能放 U 盘里用吗？**  
A：可以，本程序绿色便携，整个文件夹拷走即可。

**Q：分组顺序会保存吗？**  
A：会。拖动换位后立即保存，下次打开保持同样顺序。

**Q：怎么彻底重置？**  
A：删除程序目录下的 `config.json`，重启程序即恢复初始状态。

#### 一、修复：文件行互相重叠

##### 1. 问题现象

分组里的文件行**上下叠在一起**，文字被下一行的边框切断。

特征很明显：**只有行数较多的分组会中招**，1～2 行的分组看起来正常。

##### 2. 怎么发现的

1. **复现**：按用户截图里的配置重建分组（一个 3 行的 `test` 分组），稳定复现。
2. **截图**：用 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` 抓窗口。  
   抓之前必须先 `SetProcessDpiAwareness(2)`，否则 150% 缩放下坐标被虚拟化，  
   截出来的图会被裁掉一半。
3. **加临时调试代码**：在启动 2 秒后把每个控件的几何信息 dump 到 `geom.txt`。  
   这是定位布局问题最快的手段。

拿到的关键数据：

```
groupHost = 417 x 546     hintH = 640      ← 容器只拿到 546，内容需要 640
GROUP test  h = 120       hintH = 188      ← 分组被压到最小 120，实际需要 188
   ROW  y = 8    h = 38
   ROW  y = 28   h = 38    ← 只隔 20px，应该是 42px（38 + 4）
   ROW  y = 47   h = 38    ← 只隔 19px
```

**行高 38 是对的，但行与行的间距被压成了负数（约 −18px）**，所以后一行盖住了前一行。

##### 3. 根本原因（两层叠加）

**第一层：`QScrollArea` 只按「最小高度」撑容器**

`m_scroll->setWidgetResizable(true)` 时，滚动区把内容控件 `groupHost` 撑到  
**`max(视口高度, 布局的最小高度)`**，而**不是** `sizeHint()`。

本例中视口 546、布局最小高度也是 546（4 个分组 × 最小 120 + 间距 + 边距），  
所以容器只有 546 高，而内容其实需要 640 —— 滚动条没有可滚的余量，只能硬压。

**第二层：分组把最小高度写死成 120**

`GroupWidget` 构造函数里有 `setMinimumHeight(120)`，于是布局可以「合法地」把  
3 行的分组压到 120（它实际需要 188）。

被压之后，分组内部可用高度只剩：

```
120 − 48（标题栏）= 72px
```

但要放下：

```
8（上边距）+ 38×3（三行）+ 4×2（两个间距）+ 10（下边距）= 142px
```

**缺口 70px。**

**为什么表现成「重叠」而不是「裁掉」**

Qt 的 `QBoxLayout` 在空间不足时不会简单裁切，而是走 `qGeomCalc()`：  
把缺口按「可压缩量」分摊给所有条目，**连 spacing 也算在内**。

而文件行是 `setFixedHeight(38)`，压不动；标题栏也压不动。  
唯一能压的只有 spacing（4px），可压缩总量只有 8px，缺口却有 70px，  
于是 **spacing 被摊成负值（4 → −18）**，行与行直接叠在一起。

##### 4. 为什么只有行数多的分组中招

| 分组       | 行数    | 内容需要    | 被压到     | 缺口     | 表现       |
| -------- | ----- | ------- | ------- | ------ | -------- |
| 校园网      | 1     | 104     | 120     | 无      | 正常       |
| Project  | 1     | 104     | 120     | 无      | 正常       |
| warframe | 2     | 146     | 120     | 26     | 轻微重叠     |
| **test** | **3** | **188** | **120** | **68** | **严重重叠** |

行数越多，缺口越大，重叠越明显。`warframe` 其实也有问题（2 行只隔 29px），  
只是重叠得少，肉眼不容易发现。

##### 5. 修复过程

**第一次尝试（失败）**

思路是对的：让分组的最小高度跟随内容。

```cpp
void GroupWidget::updateMinimumHeight()
{
    const int contentH = layout() ? layout()->minimumSize().height() : 0;
    setMinimumHeight(qMax(120, contentH));
}
```

结果 `minH` 仍然是 120，等于没生效。

**失败原因：布局缓存**

`layout()->minimumSize()` 是带缓存的。刚 `insertWidget` 插入行时缓存还没重算，  
读到的是旧值（104）；要等事件循环跑完才会变成 188。  
在插入行的当下读它，读到的是过期数据。

**最终方案：先设一次 + 定时器纠正一次**

```cpp
void GroupWidget::updateMinimumHeight()
{
    QLayout *lay = layout();
    if (!lay)
        return;
    setMinimumHeight(qMax(120, lay->minimumSize().height()));   // 先按当前值设一次

    // 同一轮里可能被连续调用多次（每加一行都会调），只排一个定时器就够
    if (m_minHeightQueued)
        return;
    m_minHeightQueued = true;
    QTimer::singleShot(0, this, [this] {                        // 布局刷新后再纠正一次
        m_minHeightQueued = false;
        if (QLayout *l = layout())
            setMinimumHeight(qMax(120, l->minimumSize().height()));
    });
}
```

并在 `rebuildRows()`、`appendRow()`、删除行三处调用。

这样分组的最小高度始终等于内容真实高度，外层布局就压不动它，  
`QScrollArea` 也才能算出正确的滚动范围。

##### 6. 验证结果

| 指标       | 修复前             | 修复后                      |
| -------- | --------------- | ------------------------ |
| 容器高度     | 546（被压）         | **640**（内容高度）            |
| warframe | 120             | **146**                  |
| test     | 120             | **188**                  |
| 行位置      | 8 / 28 / 47（重叠） | **8 / 50 / 92**（42px 均匀） |

截图确认三行整齐排列，不再重叠。

##### 7. 经验总结

> `QScrollArea(widgetResizable=true)` **只按「最小高度」撑容器，不看 sizeHint**；  
> 列表项的最小高度必须**跟随内容**，不能写死。  
> 否则内容一旦超出视口，就会被外层布局压扁，  
> 而 Qt 会把 spacing 压成负值 —— 这才是「行重叠」的真正来源。

#### 二、代码优化（9 项）

原则：**不改外观、不改行为**，只消除重复的 IO、重复的布局重排、重复的对象分配。

| # | 优化项        | 优化前                       | 优化后                |
| - | ---------- | ------------------------- | ------------------ |
| 1 | 合并写盘       | 4 个分组写 4 次 / 拖 5 个文件写 5 次 | **各 1 次**          |
| 2 | 定时器合并      | 还原 10 行排 10 个定时器          | **1 个**            |
| 3 | 拖拽热路径      | 每次移动新建 QString + 重排布局     | **零分配 / 跨组才重排**    |
| 4 | 列表复制与扩容    | 每次读取复制整个列表 + 反复扩容         | **零拷贝 + 一次分配**     |
| 5 | `QDrag` 泄漏 | 每拖一次累积 1 个对象              | **0**              |
| 6 | 遍历时改列表     | 依赖「按值返回」的巧合               | **显式快照**           |
| 7 | 重复延迟代码     | 网址/文件两个分支各写一遍             | **抽成一个方法**         |
| 8 | 多余循环       | `while` 删超限行              | **`if`**           |
| 9 | 正则重复编译     | 每次改名重新编译正则                | **`static` 只编译一次** |

逐项说明：

**1）合并写盘（收益最大）**

原来每建一个分组就落盘一次：启动还原 4 个分组 → 写 4 次 `config.json`；  
一次拖入 5 个文件 → 写 5 次。每次都是完整 JSON 序列化 + 磁盘 IO。

现在加了一个批量计数 `m_batchDepth`，批量期间只同步内存：

```cpp
void MainWindow::onAnyChanged()
{
    syncGroupsToConfig();
    if (m_batchDepth == 0)     // 批量操作中先不写盘
        m_config->save();
}
```

调用方这样包起来：

```cpp
++m_batchDepth;
for (const GroupEntry &g : savedGroups)
    addGroupPanel(g.name, {}, &g);
--m_batchDepth;
m_config->save();              // 全部还原完，只存一次
```

**2）启动遍历取快照**

`addGroupPanel()` 内部会回调 `onAnyChanged()` → `setGroups()` 改动同一个列表，  
边遍历边改是典型的迭代器失效隐患。现在先取本地快照再遍历：

```cpp
const QList<GroupEntry> savedGroups = m_config->groups();   // 快照
for (const GroupEntry &g : savedGroups)
    addGroupPanel(g.name, {}, &g);
```

**3）`reserve()` 预分配**

`syncGroupsToConfig()` 里 `list.reserve(m_groupLayout->count())`，避免 QList 反复扩容。

**4）合并最小高度重算的定时器**

`appendRow()` 每加一行都会调一次 `updateMinimumHeight()`，原来每次都排一个  
`QTimer::singleShot`。现在用 `m_minHeightQueued` 标志，同一轮只排一个。

**5）修复 `QDrag` 内存累积**

`QDrag` 是 `new` 出来的，`exec()` 返回后**不会自动释放**，父对象是分组，  
所以会一直活着 —— 每拖动一次分组就多留一个 `QDrag` + `QMimeData`。  
现在 `exec()` 之后加 `drag->deleteLater()`。

**6）拖拽热路径减负**

- MIME 类型改为文件级 `static const QString`，原来每次 `DragMove`（鼠标一动就触发）  
  都要 `QString::fromLatin1` 新建一个字符串。
- `updateDropIndicator()` 增加 `m_indicatorIndex` 缓存，**位置没变直接返回**，  
  不再反复 `remove/insert` 折腾布局。拖动时每秒几十次 `DragMove`，  
  但真正跨过分组边界只有几次。

**7）消除重复代码**

`Launcher::launch()` 里「网址分支」和「文件分支」各写了一遍  
「读 delayMs + msleep」的延迟逻辑，抽成 `waitLaunchDelay()`。

**8）`while` → `if`**

`Logger::append()` 每次只加一行，超出上限删一行就够，不可能一次超多行。

**9）正则静态化**

`maybeAutoRename()` 里的 `QRegularExpression` 改为函数内 `static`，避免每次改名重新编译。

**优化验证**

- 编译**无警告**
- 截图与优化前**逐像素一致**（外观零变化）
- 行不重叠的修复**无回归**
- 拖动换位实测通过：`[校园网, warframe, Project, test]` → `[warframe, Project, 校园网, test]`
- 拖动后配置正确落盘

#### 三、其它修复：程序图标

**问题**：exe 的图标不见了，资源管理器 / 任务栏 / 标题栏都变成 Windows 默认图标。

**原因**：图标是靠 `app.rc` 里的 `IDI_ICON1 ICON "app.ico"` 写进 exe 资源的，  
而手动构建脚本 `scripts/build.sh` 从来没编译过 `app.rc`（只跑了 moc → 编译 → 链接）。

Qt Creator 走 `.pro` 里的 `RC_FILE = app.rc`，所以那边一直有图标；  
用构建脚本就会把带图标的 exe 覆盖成无图标的。

**修复**：脚本第 2 步加上资源编译，并把产物一起链接：

```bash
"$MINGW/windres.exe" -I"$PROJ" -O coff "$PROJ/app.rc" -o app_res.o
...
OBJS="$OBJS app_res.o"
```

**验证**：exe 从 356,072 涨到 360,698 字节（+4.6KB ≈ 图标大小）；  
`ExtractIconExW` 解析出 1 个图标；窗口类的大小图标句柄均非零。
